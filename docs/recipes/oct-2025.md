# Recipe: Open Character Training (OCT, 2025)

**Status: runs end to end through the orchestrator on a tiny CPU model ([scripts/oct_pipeline_smoke.py](../../scripts/oct_pipeline_smoke.py); stage-level check in [scripts/oct_smoke.py](../../scripts/oct_smoke.py)). It has never run on the pinned 4B student or on Golem.** The values are machine-readable in [recipes/oct-2025.json](../../recipes/oct-2025.json), and one command runs them:

```bash
character-pipeline run characters/golem-15 --recipe recipes/oct-2025.json --model qwen3.5-4b-base
```

Stage 2 (prompt expansion with Llama 3.3 70B) and OCT's own evaluations are still not implemented; the run uses the constitution's seed questions and our pushback environment.

## What OCT is

Open Character Training (Maiya, Bartsch, Lambert and Hubinger, 2025) trains a persona into an instruct model in two stages, both with LoRA:

1. **Distillation (DPO).** A teacher model writes "chosen" replies with the persona's constitution in its system prompt. The untrained student, given no system prompt, writes the "rejected" replies to the same prompts. The student is trained with DPO plus an NLL term on the chosen side and a small per-token KL penalty.
2. **Introspection (SFT).** The post-DPO student writes about itself (self-reflection) and talks to a copy of itself (self-interaction). A fresh LoRA is then trained on those 12,000 transcripts, on top of the DPO-folded weights.

The released adapters are a linear merge of the two LoRAs. A constitution is about 10 first-person trait statements, each with 5 hand-written seed prompts. Those 5 prompts are expanded to 50 per trait.

This card maps OCT onto this repo's commands, lists every hyperparameter with the place in OCT's code or paper it comes from, and lists every place where we differ. Source locations refer to `maiush/OpenCharacterTraining` at `d1da9f0` ("OCT"), its training fork `maiush/OpenRLHF` at `eaf40e1` ("fork"), and the paper, arXiv 2511.01689 v1 ("paper").

```bash
# 6. DPO from the bare student; the reference is the bare student
python -m character_pipeline.train.preference dpo --sft-adapter none \
  --data $R/pairs/seed0/dpo_train.jsonl --out $R/dpo/seed0 \
  --loss-type sigmoid sft --loss-weights 1.0 0.1 --beta 0.1 --lr 5e-5 --epochs 1 \
  --batch-size 1 --global-batch 32 --max-length 1024 --rank 64 --alpha 128 --lora-dropout 0 \
  --warmup 0.1 --scheduler cosine_with_min_lr --min-lr-rate 0.1 --adam-beta2 0.98 \
  --weight-decay 0 --max-grad-norm 1.0 --seed 0

# 7. Introspective transcripts from base + DPO adapter (OCT counts; slow, see deviations)
python -m character_pipeline.generate.introspection --adapter $R/dpo/seed0/adapter \
  --constitution characters/golem-15/constitution.json --out $R/introspection/seed0 \
  --reflection-n 1000 --interaction-n 1000 --turns 10 \
  --reflection-max-new-tokens 2048 --interaction-max-new-tokens 1024 --seed 0 --validation-n 200

# 8. Merge the DPO adapter into the weights, then train a fresh LoRA
python -m character_pipeline.train.sft --merge-adapter $R/dpo/seed0/adapter \
  --train $R/introspection/seed0/train.jsonl --validation $R/introspection/seed0/validation.jsonl \
  --out $R/sft/seed0 --epochs 1 --lr 5e-5 --accumulation 32 --seq-len 3072 --rank 64 --alpha 128 \
  --lora-dropout 0 --weight-decay 0 --warmup 0.1 --min-lr-rate 0.1 --adam-beta2 0.98 --seed 0
#    add --supervise last for the strict replica of OCT's code (see deviations)

# 9. Merge the two adapters (OCT code weights)
python -m character_pipeline.train.merge --dpo $R/dpo/seed0/adapter --sft $R/sft/seed0/adapter \
  --out $R/persona/seed0 --weights 1.0 0.25
```

`--validation-n 200` is our own addition; OCT holds nothing out. The value is illustrative. With `--validation-n 0` (the default), every transcript goes to `train.jsonl`, and `--validation` must then point at a separate file.

Every new flag defaults to the current behaviour: the existing SFT, DPO, KTO and continued-SFT arms are unchanged unless an OCT flag is passed. The CPU check is `PYTHONPATH=. python scripts/oct_smoke.py`.

| Value | OCT | Source | Here |

**The paper does not state the merge weights.** §2.4 says only that the adapters are "linearly merged". `merge_loras.py` loads the SFT adapter from a `{family}-test` path, not `-introspection`, so it is not certain that 1.0 / 0.25 produced the released adapters. PEFT's `linear` mode also adds `sqrt(w)`-scaled A and B matrices separately. The merged update therefore contains cross terms and is not the weighted sum of the two deltas. `--combination-type cat` gives the exact sum.

## Deviations

From OCT's setup:

1. **Base, not instruct, student.** Our student is `Qwen/Qwen3.5-4B-Base`. OCT uses Llama 3.1 8B Instruct, Qwen 2.5 7B Instruct and Gemma 3 4B it (paper §2.3). OCT's rejected side is an instruct reply given no system prompt. Ours is a Base completion under the chat template, which is a much weaker negative. A faithful comparison needs a pinned Instruct revision, which RECIPE.md does not have yet.
2. **Teacher model.** We use Qwen3-30B-A3B (local GGUF). OCT uses GLM 4.5 Air, with a `<think>` prefill whose trace is dropped (`teacher.py:136, 155-162`). A single-turn OCT-style teacher pass over constitution prompts is not implemented.
3. **No LIMA.** OCT adds the first turn of every LIMA conversation to the DPO prompts (`teacher.py:96-108`). LIMA is CC BY-NC-SA, and so is OCT's released data, so neither is used. The prompt mix is therefore constitution-only, and much smaller than OCT's roughly 6M DPO tokens per persona (paper App. A).
4. **No prompt expansion.** Stage 2 is not implemented. We have 5 seed prompts per trait, not 50.
5. **No KL term.** OCT's DPO adds `0.001 × mean((log π − log π_ref)²)` over the chosen and rejected completion tokens (fork `dpo_trainer.py:178, 386-402`), a k2-style estimator. TRL 1.14.1 has no such option, and we did not port it. Every run with an `sft` loss term writes this, and the next two items, under `deviations` in `training_summary.json`.
6. **NLL normalisation.** TRL's `sft` term (checked in the installed `trl/trainer/dpo_trainer.py`, the `loss_type == "sft"` branch) is a cross-entropy averaged over all chosen tokens in the batch, added as `weight × loss`. The fork averages per sample, then over the batch (`dpo_trainer.py:324`).
7. **Precomputed reference.** Our DPO precomputes reference log-probs once. OCT runs the reference live. For a frozen reference the two are equivalent up to numerical precision.
8. **All-turn vs last-turn supervision.** `train.sft` supervises every assistant turn by default. OCT's SFT has no `--multiturn`, so it supervises only the final message. `--supervise last` reproduces OCT's code. Our self-interaction rows end on the final reply, so in that mode the target is the last generated reply. In all-turn mode, the fixed opening greeting also counts as an assistant turn when K is even, and is supervised.
9. **Self-interaction rows.** OCT's saved rows appear to end on the last prompt, a user-role message (`self_interaction.py:167-183`). That would make the final user turn the supervised target. This has not been confirmed against the released data. We save the final turn's prompt plus its reply.
10. **Guidance line included.** In OCT's code the self-interaction template has no `{guidance}` placeholder (`self_interaction.py:28-35, 150`), so the free and leading modes differ only in their greetings. We follow the oliveradk port and include the line, which is what the paper (App. B.2) describes.
11. **Seeds.** OCT samples all data with `seed=None` and trains with seed 123456. We seed every generation call (the seed is stored with the row) and use the run's seeds. Self-interaction greetings and the final shuffle are seeded too (OCT: `random.choices`, and an unseeded `sample(frac=1)`).
12. **Generation engine.** Introspection runs through transformers one sequence at a time, not with batched vLLM. That is slow at OCT's scale: about 10,000 reflections and 20,000 interaction turns. We also do not left-truncate long self-interaction prompts. OCT truncates to `max_model_len − max_new_tokens`; `train.sft` drops over-length transcripts instead.
13. **Hardware and precision.** OCT trains in bf16 on DeepSpeed ZeRO-2 across an unstated number of GPUs. Here, global batch 32 is micro-batch 1 × accumulation 32 on one GPU, with fp16 weights on a T4.
14. **SFT schedule rounding.** `train.sft` uses Aineko's own schedule with a floor. It rounds warm-up steps down and offsets cosine progress by one update, relative to transformers' `cosine_with_min_lr`, which rounds up. The DPO stage uses the transformers function itself.
15. **Student sampling.** `train.sample` does not expose top-k or repetition penalty, so OCT's student settings (top-k −1, penalty 1.1; `student.py:14-20`, `utils.py:106`) are only partly applied. The punctuation filter on pairs (`distillation/data.py:15-18`) is not implemented.
16. **No quality gates on OCT data.** Introspective text does not go through our fabrication checker or the d1 judge.
17. **Evaluations.** None of OCT's evaluations are implemented. Compare arms on the pushback environment.

### Discrepancies inside OCT itself

These were found while reading OCT. They are recorded so that nobody "fixes" our recipe towards one side without knowing about the other.

- The README's download list names Qwen2.5-72B-Instruct, while the code, scripts and paper use Qwen 2.5 7B.
- The paper describes free and leading guidance for self-interaction (App. B.2). The template drops it (item 10 above).
- Self-interaction rows appear to end on a user turn (item 9 above).
- The paper names a per-token KL penalty but gives no coefficient. The script sets 0.001.
- The paper lists temperature, top-p and min-p (App. A, B). The code also applies repetition penalty 1.1.
- The merge weights appear only in code, with a `-test` SFT path (stage 9).
- The prefill follow-up is "Tell me more" in the paper (§3.3) and "Keep going." in `prefill/multi_turn.py:105`.
- The coherence judge temperature is 0.1 in the paper (§3.4) and 0.7 in `coherence.py:46`.
- The trait list has 144 entries according to App. G, and "about 150" according to §3.1.
- The preference eval uses 25,000 samples according to §3.1; the code defaults to the full dataset.
- `gen_prompts.py:138` reads a `clarification` field that no hand-written constitution has.

## Before comparing with our arms

Run OCT on Golem as a fifth arm with the same seeds and probes. Report tokens trained per stage, plus a token-matched variant, so that recipe and data scale are not confounded. Our 0.8B "OCT-lite" run (Aineko: DPO, then introspective SFT) got worse: 7/8 adversarial breaks, against 3/8 for SFT alone. Its hyperparameters were not OCT's, so a faithful 4B replica is still an open test.
